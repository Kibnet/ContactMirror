# ContactMirror

Контакты Google в обычной папке на Windows. Ручная двусторонняя синхронизация: приложение сначала показывает изменения, затем применяет выбранные. Один контакт — один редактируемый JSON-файл; фотографии и ярлыки хранятся отдельно.

Рабочий Desktop OAuth client подготовлен и включается в установщик при сборке. Настоящий вход и чтение каталога Google проверены в установленной IntegrationValidation. Проект Google пока использует тестовую аудиторию; публичный выпуск и общий сервер обновлений ещё не подготовлены. Результаты экспорта, установки и обновления фиксируются отдельно в [docs/VALIDATION.md](docs/VALIDATION.md).

## Запуск

Нужен Windows x64. Portable-сборка содержит .NET; для запуска из исходников нужен .NET SDK 10.0.401.

После установки используйте ярлык ContactMirror. В распакованном Velopack portable запускайте `ContactMirror.exe` в корне ZIP; основной EXE находится в `current/ContactMirror.exe`. Для знакомства запустите `current/ContactMirror.exe --demo`. ZIP нужно распаковать целиком: EXE использует соседние библиотеки. В демо можно безопасно проверить двусторонний цикл на вымышленных контактах; используйте отдельную пустую папку.

```powershell
dotnet run --project src/ContactMirror.Desktop -- --demo
```

Демо использует вымышленные контакты и отдельное состояние. Выберите новую пустую папку, подключите демо-аккаунт, нажмите «Проверить изменения», затем «Применить». Отредактируйте JSON-файл, проверьте изменения снова. Демо не обращается к Google.

Обычный режим:

```powershell
dotnet run --project src/ContactMirror.Desktop
```

В установщике подключение поставляет издатель: нажмите «Подключить Google» и подтвердите доступ в браузере. Для разработки можно импортировать свой Desktop OAuth client; подробности в [docs/GOOGLE_SETUP.md](docs/GOOGLE_SETUP.md).

## Как пользоваться

1. Подключите аккаунт через системный браузер и выберите папку.
2. Нажмите «Проверить изменения». Просмотрите направления, значения и сообщения о неподдерживаемых полях.
3. Выберите сторону для каждого конфликта. Удаления изначально не выбраны и требуют отдельного подтверждения.
4. Примените выбранное. При частичном результате выполните новую проверку; приложение сверит незавершённые операции перед повтором.
5. Для отката выберите запуск в истории. Восстановление также сначала показывает план и создаёт резервную копию. Если до выбранного запуска стороны отличались, «Из папки» и «Из Google» выбирают источник из копии; выбранное значение записывается в обе стороны.

Сохранение из Google в папку использует уже загруженный и показанный снимок, включая фотографии. Повторных запросов Google перед таким сохранением нет. Если данные на сервере изменились позже, нажмите «Проверить изменения» вручную. Запись в Google и удаления сохраняют проверки актуального состояния; изменения локальных файлов после просмотра плана также проверяются.

Редактировать можно `data`, `labels`, `starred`, `photo` и `extensions`. Раздел `google` хранит полный снимок API и доступен только для чтения. Полный формат и ограничения описаны в [docs/FORMAT.md](docs/FORMAT.md).

Просмотр изменений показывает конкретные поля и значения, а для фото — текущие изображения. Если вместе с обычными полями случайно изменён `google`, кнопка «Исправить служебную копию» восстановит только этот раздел, сохранив все ваши правки и резервную копию. Затем вручную проверьте изменения и отправьте выбранные поля и фото в Google.

## Проверка и сборка

```powershell
dotnet build ContactMirror.sln -c Release
dotnet test tests/ContactMirror.Tests -c Release
dotnet test tests/ContactMirror.GoogleTests -c Release
dotnet run --project tests/ContactMirror.UiTests.Headless -c Release -- --maximum-parallel-tests 1
dotnet run --project tests/ContactMirror.UiTests.FlaUI -c Release -- --maximum-parallel-tests 1
dotnet publish src/ContactMirror.Desktop -c Release -r win-x64 --self-contained true -o artifacts/ContactMirror-win-x64
```

UI-проекты используют TUnit/AppAutomation, поэтому запускаются отдельно от xUnit-проектов. Native-проверки используют тестовый аккаунт и управляемые сценарии, а не реальный Google. Подробности фактически выполненных проверок — в [docs/VALIDATION.md](docs/VALIDATION.md).

Установщики и пакеты обновления создаются скриптом [scripts/Build-Release.ps1](scripts/Build-Release.ps1), Velopack SDK/CLI закреплены на 1.2.0. Команды и профили описаны в [docs/RELEASE.md](docs/RELEASE.md). Проверка обновлений не устанавливает их автоматически: загрузку и перезапуск выбирает пользователь в настройках.

## Хранение данных

JSON, фотографии, SQLite-состояние, корзина и резервные копии остаются в выбранной папке. Они содержат персональные данные контактов. Токены OAuth находятся отдельно в LocalAppData и защищены Windows DPAPI для текущего пользователя. Токены не включаются в резервную копию адресной книги. Не редактируйте `.contactmirror` вручную.

Синхронизация не является общей транзакцией Google и диска. Успешная запись в Google может предшествовать ошибке локального сохранения; журнал сохраняет результат и связь, а повторная проверка показывает дальнейшие действия. Некоторые endpoints Google не имеют условной записи: это ограничивает защиту от одновременной правки на сервере.
