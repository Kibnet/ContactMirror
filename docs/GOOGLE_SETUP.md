# Google: разработка и публичный выпуск

Для готового установщика OAuth client поставляет издатель: пользователю достаточно нажать «Подключить Google» и подтвердить доступ в системном браузере. Пароль приложение не получает.

2026-10-07 подготовлен проект `contactmirror-desktop-20261007`, включён People API, создан Desktop OAuth client «ContactMirror Windows», добавлен тестовый пользователь. В установленной IntegrationValidation выполнен настоящий вход и прочитан каталог Google. Первое применение массового экспорта остановилось на HTTP 429; исправление и повторная проверка фиксируются в `VALIDATION.md`. Публичная аудитория и проверка Google ещё не завершены; текущий проект использует External / Testing.

1. Создайте или выберите собственный Google Cloud проект.
2. Включите People API, настройте OAuth consent screen и тестовую аудиторию.
3. Создайте Desktop OAuth client и скачайте его JSON.
4. Для собственной developer-сборки откройте настройки и импортируйте JSON. Приложение сохраняет управляемую копию вне установочной папки; исходный файл больше не нужен для повторного запуска.
5. Войдите через браузер. Для первых записей используйте отдельный тестовый аккаунт с вымышленными контактами.

Для запуска из исходников порядок выбора: управляемый импорт → пара environment `CONTACTMIRROR_GOOGLE_CLIENT_ID` / `CONTACTMIRROR_GOOGLE_CLIENT_SECRET` → `appsettings/oauth-client.local.json` рядом с EXE → такой же файл в текущем каталоге → конфигурация издателя `appsettings/oauth-client.json`. Установленная Production-сборка использует управляемый импорт либо конфигурацию издателя. Неверная конфигурация выбранного источника останавливает вход; параметры разных клиентов не смешиваются.

IntegrationValidation всегда использует только конфигурацию издателя. Synthetic Validation отключает Google и работает с вымышленными данными. Токены этих профилей и обычного приложения хранятся отдельно. Локальный JSON исключён из Git; refresh/access tokens и пароль не включаются в исходники или пакеты.

Используемые разрешения: `openid`, `email`, `https://www.googleapis.com/auth/contacts`. Вход использует PKCE S256, state/nonce, loopback callback и проверку подписи ID token. Доступ можно отключить в приложении; отзыв со стороны Google также должен приводить к повторному подключению.

Для удобного подключения других людей издатель должен поставить собственный client в `appsettings/oauth-client.json`, выполнить применимую проверку OAuth sensitive scope и проверить production-аудиторию. Отдельно нужны публичные страницы продукта, privacy policy, поддержка и требования Google к брендингу. Эта локальная сборка не объявляется прошедшей такую проверку.

Вход ожидает callback пять минут. Если время истекло, повторите подключение и завершите вход в новой вкладке; старый callback уже не принимается. HTTP 429 означает ограничение запросов, а не необходимость нового входа. При чтении приложение делает ограниченное число повторов с паузами и поддержкой отмены; запросы изменения контактов автоматически не повторяются.

Первичные источники: [Desktop OAuth](https://developers.google.com/identity/protocols/oauth2/native-app), [People API](https://developers.google.com/people), [Sensitive scope verification](https://developers.google.com/identity/protocols/oauth2/production-readiness/sensitive-scope-verification). API-контракт реализации зафиксирован по discovery revision 20261004, проверенному 2026-10-06.
