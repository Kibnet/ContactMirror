# Формат папки v1

```text
contacts/<UUID>.contact.json
groups/<UUID>.group.json
photos/<UUID>-<hash>.png или .jpg
.contactmirror/workspace.json
.contactmirror/state.db
.contactmirror/backups/<run-id>/
.contactmirror/trash/<run-id>/
```

Папка привязана к проверенной личности Google (`issuer` + `sub`), а не к отображаемому email. Демо имеет собственный issuer. Другой аккаунт не может использовать ту же папку. Имя файла и подпапка могут меняться; идентичность задаёт UUID внутри файла. Два файла с одинаковым UUID блокируют операции с этой записью.

Пример нового контакта:

```json
{
  "schemaVersion": 1,
  "id": "f137b220-8b4b-48f9-a262-9347946d91b0",
  "data": {
    "names": [{ "givenName": "Анна", "familyName": "Примерова" }],
    "phoneNumbers": [{ "value": "+7 000 000-00-01", "type": "Работа" }],
    "emailAddresses": [{ "value": "anna@example.test", "type": "work" }],
    "birthdays": [{ "date": { "year": 0, "month": 5, "day": 12 } }]
  },
  "labels": [],
  "starred": false,
  "photo": null,
  "extensions": { "localNote": "Произвольные локальные данные" },
  "google": null
}
```

`data` содержит редактируемую часть источника CONTACT: addresses, biographies, birthdays, calendarUrls, clientData, emailAddresses, events, externalIds, genders, imClients, interests, locales, locations, miscKeywords, names, nicknames, occupations, organizations, phoneNumbers, relations, sipAddresses, urls, userDefined. Повторяющиеся значения и пользовательские типы сохраняются. Внутри категорий используются имена и типы Google People API; списки категорий сравниваются без учёта порядка, с сохранением кратности.

Отсутствующая категория `data` и пустой массив означают очистку этой категории. `null` внутри редактируемых значений запрещён. names, birthdays, biographies и genders допускают одну запись. Поддерживаются частичные даты. `metadata.sourcePrimary` позволяет выбрать основную запись; другие метаданные источника относятся к снимку только для чтения.

`labels` — UUID пользовательских ярлыков из `groups`. `starred` — избранное. Фото — относительный путь внутри `photos`; изменение байтов по прежнему пути распознаётся. Для удаления фото задайте `photo: null`; отсутствие указанного файла считается ошибкой, а не удалением. Принимаются JPEG/PNG до 20 МБ с ограниченными размерами декодирования.

Доступные недефолтные изображения PROFILE и обложек кешируются в `.contactmirror/cache`. Ссылки на локальные копии и SHA-256 находятся в `google.readOnlyImages`. Эти изображения не становятся редактируемым CONTACT-фото. При восстановлении неизвестного создания сохранённое намерение загрузки фото остаётся отдельным пунктом; новая локальная правка имеет приоритет над старым намерением.

`google.person` содержит полный снимок, включая поля PROFILE, служебные и ещё неизвестные поля. Они сохраняются, но не превращаются в доступные для записи. Если новая неизвестная вложенная структура может исчезнуть при замене категории, запись этой категории блокируется. PROFILE не копируется в CONTACT автоматически. `extensions` сохраняется локально и не отправляется в Google.

Пример ярлыка:

```json
{
  "schemaVersion": 1,
  "id": "a5525499-e6bb-49c8-9c28-328b06e4eadc",
  "name": "Друзья",
  "clientData": [],
  "extensions": {},
  "google": null
}
```

Неизвестная версия, некорректный JSON, дубликат ключа, неверный тип, ссылка за пределы папки или неоднозначный источник Google блокируют затронутую операцию. Полностью пустая папка контактов с прежним состоянием не считается намерением массово удалить Google. При утрате состояния действует восстановление с отключёнными удалениями.

Резервная копия сохраняет версии до запуска для обеих сторон, фотографии и состояние связи. Восстановление заново сравнивает текущую папку и Google. Восстановление удалённого контакта Google получает новый идентификатор. Отмена первого скачивания может убрать созданный локальный файл, сохранив существовавшую запись Google.

Если локальная и Google-версия ДО запуска различались, восстановление показывает конфликт источников копии. Например, до загрузки нового телефона локально был B, а в Google A: выбор «Из Google» вернёт A в обе стороны; выбор «Из папки» сохранит B в обеих. Текущие версии будут сохранены в новой резервной копии. Это согласование выбранной версии, а не невидимая перезапись сторон разными значениями.

При обнаруженной гонке атомарного переименования фактически вытесненные байты сохраняются в `.contactmirror/recovery/displaced`. Незавершённое намерение замены или явная гонка блокируют затронутую запись. Сообщение указывает копию; сохраните нужную версию в основной файл и уберите соответствующий служебный marker только после ручной сверки обеих версий. Остальные данные и полный backup остаются доступны. Проверки существующих ссылок не являются kernel sandbox против злонамеренной подмены каталогов между проверкой и вызовом файловой системы.

Схемы для редакторов: `schemas/contact.schema.json`, `schemas/group.schema.json`; вымышленные примеры — `examples/`. Приложение дополнительно проверяет существование ярлыков/фотографий, связь аккаунта и неизменность служебного снимка.

В истории показывается объём копий. Удалить выбранную копию можно только с подтверждением и только для завершённого/восстановленного запуска без незавершённых операций. Это не удаляет контакты и запись в истории, но отменяет возможность отката по этой копии. Корзина и вытесненные версии файлов не входят в это действие.
