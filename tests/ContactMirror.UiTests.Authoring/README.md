# Проверка интерфейса ContactMirror

UI проверяется на настоящем `MainWindow` с подменёнными `IAccountConnector` и `ISyncCoordinator`. TestHost не открывает Google, не читает реальные контакты и не записывает их. На экране явно показано, что данные вымышленные. Обычное приложение использует настоящую инфраструктуру; `--demo` использует отдельный локальный провайдер.

Каноническая структура получена из `AppAutomation.Templates` 1.9.0. Пакеты AppAutomation закреплены на 1.9.0, Avalonia — на 12.1.3, TUnit — на 1.61.29. Headless и FlaUI наследуют сценарии из Authoring. Сборки выполняются последовательно.

```powershell
dotnet build tests/ContactMirror.UiTests.Headless/ContactMirror.UiTests.Headless.csproj
dotnet run --project tests/ContactMirror.UiTests.Headless/ContactMirror.UiTests.Headless.csproj --no-build -- --maximum-parallel-tests 1

# Только Windows с доступным интерактивным рабочим столом:
dotnet build tests/ContactMirror.UiTests.FlaUI/ContactMirror.UiTests.FlaUI.csproj
dotnet run --project tests/ContactMirror.UiTests.FlaUI/ContactMirror.UiTests.FlaUI.csproj --no-build -- --maximum-parallel-tests 1
```

Общие сценарии: подключение → предварительный план → выбор версии конфликта → частичный результат; поиск и выбор Google/отложить; исходно невыбранные удаления, запрет блокированного поля и подтверждение значительных удалений; история → план восстановления без немедленной записи. Дополнительно Headless проверяет остановку ожидающего сравнения, пустой экран в тёмной теме при 1000×680 и обязательное подтверждение удаления ярлыка через разрешение конфликта «Взять из папки».

UX-сценарии Headless проверяют connect-first с невалидным/валидным путём, группировку по EntityId при одинаковых именах, точные полевые choices, relink/retry и collision, hidden selection и поиск по значениям, failed/unknown/unattempted, raw technical values и буквальные JSON-looking строки, modal guards и focus/Escape. Компактный конфликт проверяется в 1000×680 и 820×640 по видимым значениям и viewport bounds; светлая/тёмная темы — по PNG и контрасту ресурсов. Настройки закрываются с сохранением контекста. FlaUI дополнительно проверяет клавиатуру и ordinary Desktop `--demo` с временной папкой; исходный `desktop-demo.json` восстанавливается после этого smoke.

Отдельный общий сценарий запускает реальные `DemoAccountConnector`, `DemoGoogleGateway` с уникальным временным remote JSON, `SyncCoordinator` и `FileWorkspaceStore`. Проверяется экспорт шести контактов, изменение телефона в файле, предварительный план загрузки, применение, подтверждённый телефон в состоянии провайдера и следующее сравнение без изменений. Native TestHost получает `--integration-demo <temp-root>`; его данные и настройки изолированы. Снимки этой проверки помечены `integrated-*` и `headless`/`native`.

Очистка резервных копий проверяется дополнительно в Headless: завершённый run требует отдельного подтверждения; удалённая копия отключает восстановление; незавершённый partial run не допускает очистку. Ни одна из этих проверок не использует настоящие контакты Google.

Большая адресная книга проверяется двумя Headless-сценариями. Синхронная работа координатора до первого `await` выполняется в отдельном потоке; 10 000 сообщений прогресса не заполняют UI-очередь, а кнопка отмены остаётся доступной. Второй сценарий загружает план из 10 000 изменений, считает реально созданные `ListBoxItem` в визуальном дереве и находит последний контакт через поиск. Это проверка отзывчивости и виртуализации UI; производительность настоящего координатора измеряется отдельным benchmark.

PNG сохраняются в `chat-artifacts/ui/<timestamp>/`. Headless захватывает настоящую отрисованную область Avalonia. Нативный интеграционный сценарий разворачивает тестовое окно и захватывает его через `PrintWindow` с физическими границами и DPI-контекстом потока: в кадре есть системная рамка, а перекрывающие уведомления и панель задач не попадают в снимок. Стандартный захват FlaUI на текущем масштабировании Windows давал неверные границы, поэтому для этого сценария добавлен отдельный тестовый helper. Снимки просмотрены; проверка выполнена на текущем интерактивном мониторе, без матрицы отдельных 100/150/200% режимов. Реальный Google OAuth, браузер входа и native folder picker этими сценариями не проверяются. Используемый harness сохраняет PNG, но не записывает видео; для первого приложения meaningful baseline отсутствует.

```powershell
dotnet tool restore
dotnet tool run appautomation doctor --repo-root . --strict
```

На текущей машине локальный запуск Tooling столкнулся с устаревшим глобальным `toolResolverCache`: запись версии 1.9.0 указывает на отсутствующий DLL из прежнего временного каталога. Глобальный cache не изменялся. Равнозначная проверка выполнена непосредственно закреплённой опубликованной сборкой:

```powershell
dotnet "$env:USERPROFILE/.nuget/packages/appautomation.tooling/1.9.0/tools/net8.0/any/AppAutomation.Tooling.dll" doctor --repo-root . --strict
```

Doctor показывает структуру и зависимости; его результат не заменяет прохождение сценариев и просмотр PNG. Результаты фактических прогонов приведены в общей документации проекта.
